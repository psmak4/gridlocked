# M2.5 Move to TanStack Start Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the app runs on TanStack Start instead of Next.js, with every M0–M2 guard rail intact, before M3 adds screens that would make the move bigger.

**Architecture:**
- **Framework.** Vite builds the app with the TanStack Start plugin; Nitro builds the Node server that `pnpm start` runs (`.output/server/index.mjs`). File routes live in `src/routes/`, and the generated `src/routeTree.gen.ts` is committed.
- **Reference.** The unmerged branch `spike/framework-start` did this conversion (commit `a1b4edd`). Copy its approach, not its spike-only code: nothing under `src/spike/`, `spikes/`, `e2e/spike/` or the spike routes comes across.
- **Untouched.** The scheduler and data layers (`neon.ts`, `src/jobs`, `src/providers`, `src/db`, `src/results`, `src/reference`, `src/replay`, `src/settings`) don't change. Their tests are the proof.

**Tech Stack:** TanStack Start and Router, Vite, Nitro, React 19, Tailwind CSS 4, TypeScript strict, Vitest, Playwright, ESLint 9.

**Spec:**
- [docs/design/01-high-level-design.md](../design/01-high-level-design.md) decision 3, §11.4 (response rules) and §11.5;
- [docs/design/04-implementation-plan.md](../design/04-implementation-plan.md) M2.5;
- [docs/spikes/framework-hosting.md](../spikes/framework-hosting.md), the evidence and the traps.

## Review Focus
1. **A visitor whose JavaScript hasn't loaded** (slow phone, blocked bundle). Expected: the server HTML alone carries the title, description, `lang`, stylesheet and theme script, so the page looks right before hydration. *Pinned in Task 1.*
2. **A mistyped URL.** Expected: a 404 status with a real page (heading and footer), never cached. *Pinned in Task 3.*
3. **An error response that a route had marked cacheable** (the spike's `public, s-maxage=60` on a 500). Expected: every response with status 400 or above goes out `private, no-store`. *Pinned in Task 3.*
4. **The fonts silently falling back** after `next/font` is replaced. Expected: the display font used by the heading is actually loaded. *Pinned in Task 1.*
5. **The scheduler breaking on its next deploy** because `package.json` gains `"type": "module"`. Expected: the next staging deploy bundles and runs the tick as before. *Pinned in Task 4.*

### Task 3: Never cache error responses

**Files:**
- Create: `src/server/no-store-errors.ts`, `src/server/no-store-errors.test.ts`, `src/start.ts`, `e2e/errors.spec.ts`
- Modify: `src/routes/__root.tsx` (a `notFoundComponent`), `src/routeTree.gen.ts` (regenerated)

**Interfaces:**
- Consumes: Task 1's root route.
- Produces:
  - `function noStoreOnError(response: Response): Response` in `src/server/no-store-errors.ts`. For a status of 400 or above it sets `Cache-Control: private, no-store`, replacing any value, and returns the response; anything below 400 comes back untouched.
  - `startInstance` in `src/start.ts`: `createStart(() => ({ requestMiddleware: [noStoreErrors] }))`, where `noStoreErrors` is a `createMiddleware().server(...)` that passes the result's response through `noStoreOnError`.
  - The root route's `notFoundComponent`: `<main className="p-space-4">` holding `<h1 className="font-display text-[32px] uppercase">Page not found</h1>`.

- [ ] **Step 1: Write the failing tests.**
  - Unit (`no-store-errors.test.ts`): a 500 carrying `public, s-maxage=60, stale-while-revalidate=300` comes back `private, no-store` (Review Focus 3); a 404 with no header comes back `private, no-store`; a 200 with `public, s-maxage=60` and a 304 come back unchanged.
  - E2E (`errors.spec.ts`): `request.get("/no-such-page")` has status 404 and `cache-control` `private, no-store`; `page.goto("/no-such-page")` shows the heading `Page not found` and the footer copy (Review Focus 2).
- [ ] **Step 2:** Run `pnpm test src/server/no-store-errors.test.ts` and `pnpm build && pnpm e2e e2e/errors.spec.ts`. Expected: FAIL (no module; no header, no heading).
- [ ] **Step 3:** Implement `noStoreOnError`, `src/start.ts` and the `notFoundComponent`. The spike didn't use `createStart`, so check Start 1.169's global middleware docs first. If request middleware can't change the final response of a 404 or a thrown error, stop and record a ruling; the fallback is Nitro's response hook, calling the same `noStoreOnError`.
- [ ] **Step 4:** Run `pnpm test && pnpm build && pnpm e2e`. Expected: PASS, with the smoke tests unchanged (the home page is a 200 and keeps its headers).
- [ ] **Step 5:** Commit: `feat: never cache error responses (HLD §11.4)`.
